Project architecture

A modular structure makes experimentation safer.

The project separates data work, training, inference, application routes, and reusable utilities so each responsibility is easy to understand and test.

src/
├── components/
│   ├── data_ingestion.py # read and split data
│   ├── data_transformation.py # sklearn pipelines
│   └── model_trainer.py # tune and select models
├── pipeline/
│   └── predict_pipeline.py # serve predictions
├── logger.py
├── exceptions.py
└── utils.py
artifacts/ # raw data, splits, preprocessor.pkl, model.pkl
app.py # Flask routes and presentation layer

Key responsibilities

components/
Reusable training-stage units.
pipeline/
Inference contract used by the UI.
artifacts/
Versioned outputs needed to reproduce prediction behavior.
logger.py & exceptions.py
Observability and consistent error context.
utils.py
Serialization and GridSearchCV evaluation helpers.
